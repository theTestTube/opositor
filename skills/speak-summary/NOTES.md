# speak-summary — local installation notes

Skill adapted from [github/awesome-copilot](https://github.com/github/awesome-copilot/blob/main/skills/speak-summary/SKILL.md)
to turn study scripts into audio. `SKILL.md` is the upstream document; the changes live in `scripts/` and are
explained here.

## Two engines, and why

| Engine | Voices | Speed | Account |
|---|---|---|---|
| **Piper** (default here) | Neural voices per language | Far above real time | None |
| `pocket-tts` (upstream) | Multilingual, short catalogue | Similar or slower | Cloning requires a login |

Piper wins for studying: a voice in the profile's language, no registration, small models that are fast on CPU.
`pocket-tts` stays available with `SPEAK_ENGINE=pocket`.

The third route — and the one that installs nothing — is the **listen page** generated by
`scripts/opositor.py tts-page`: it uses the browser's voice and is good for reviewing, but it produces no files.

## Where each piece lives

| Piece | Path |
|---|---|
| Piper environment | `~/.cache/opositor/piper-venv` |
| Voice models (`.onnx` + `.json`) | `~/.cache/opositor/voices` |
| `pocket-tts` environment | `~/.cache/speak-summary/venv` |
| Voice-watch state | `~/.cache/opositor/voice-watch` |

## Preparing the engine

The `setup` skill does this, not the user. By hand it would be:

```bash
python3 -m venv ~/.cache/opositor/piper-venv
~/.cache/opositor/piper-venv/bin/python -m pip install piper-tts
```

`ffmpeg` is also needed to write MP3 (without it, the script leaves a WAV). Voice models are downloaded from the
Piper catalogue and left in the voices directory with their `.json` beside them.

## Usage

```bash
skills/speak-summary/scripts/tts.sh input.txt output.mp3
skills/speak-summary/scripts/tts.sh input.txt output.mp3 en_US-lessac-medium
SPEAK_PIPER_LANG=fr skills/speak-summary/scripts/tts.sh input.txt output.mp3
SPEAK_ENGINE=pocket skills/speak-summary/scripts/tts.sh input.txt output.mp3
```

The correct flow is **rewrite for the ear → synthesise**, not dumping written text as is. The script rules are in
`references/audio.md`.

## Choosing a voice

- The language comes from `SPEAK_PIPER_LANG` (default `en`), which `setup` sets from the profile's language.
- A specific voice is passed as the third argument or with `SPEAK_PIPER_VOICE`.
- If the directory has several voices in the same language, the first by alphabetical order wins. Rename them if
  you want to control the default.

## Speed

Piper runs well above real time on CPU: a 20-minute summary takes under a minute. `pocket-tts` is noticeably
slower; use it only if you want its timbre.

## Watching for new voices (optional)

`scripts/voice-watch.py` compares the catalogue with the previous snapshot and reports anything new. It downloads
and installs nothing. It can be scheduled with a user systemd timer, cron or the system scheduler:

```bash
python3 skills/speak-summary/scripts/voice-watch.py --status
python3 skills/speak-summary/scripts/voice-watch.py
```

The language is set with `SPEAK_WATCH_LANG` (default `en`, or a code such as `es`); the default is the English
catalogue.

## Chaining with the main skill

A useful pattern: `opositor` (find sources or generate an exam) → spoken script → `speak-summary` → MP3 for the
car or a walk. If the user only wants to listen, the listen page is faster and does not depend on Piper.
